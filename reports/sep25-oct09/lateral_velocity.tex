\section{Lateral velocity of the ego: old code vs new code}

% ---------------------------------------------------------------------------
\subsection{The issue}
\begin{itemize}
  \item The DIPF potential commands a lateral acceleration $a_y = -\partial U/\partial y$ (up to $3~\mathrm{m/s^2}$).
  \item In the \textbf{old code} the ego barely moves sideways: lane changes are rare and very slow.
  \item Cause: the lateral velocity $v_y$ is read back from SUMO every step, and SUMO always returns $0$.
  \item The \textbf{new code} keeps $v_y$ as controller state, so the push builds up into real lateral motion.
\end{itemize}

% ---------------------------------------------------------------------------
\subsection{Old code: $v_y$ is re-read from SUMO every step}
Files: \texttt{v2/run1/dipf\_controller.py}, \texttt{Pure\_DIPF\_codes.py}.
\begin{lstlisting}
vx = traci.vehicle.getSpeed(EGO_ID)
vy = traci.vehicle.getLateralSpeed(EGO_ID)        (*\color{codebad}\# always 0 for the ego*)

ay = clamp(-dUy, -AY_MAX, AY_MAX)
vy_apply = clamp(vy + ay*dt, -VY_MAX, VY_MAX)     (*\color{codebad}\# computed, never stored*)
y_new = y + vy*dt + 0.5*ay*dt**2                  (*\color{codebad}\# vy = 0: only 0.5*ay*dt**2 is left*)
traci.vehicle.moveToXY(EGO_ID, ..., x_new, y_new, ...)
\end{lstlisting}
\begin{itemize}
  \item The longitudinal speed works: \texttt{setSpeed()} stores it in SUMO and \texttt{getSpeed()} reads it back.
  \item There is no equivalent for the lateral speed.
\end{itemize}

% ---------------------------------------------------------------------------
\subsection{Why SUMO returns $v_y = 0$}
\begin{itemize}
  \item Sublane model (\texttt{--lateral-resolution 0.25}, lane-change model SL2015): lanes are split into
        $0.25~\mathrm{m}$ sublanes, vehicles can sit at any lateral position and move sideways gradually.
  \item \texttt{getLateralSpeed()} returns the lateral speed \textbf{commanded by SUMO's lane-change model},
        not the measured motion.
  \item The ego's lane-change model is disabled (\texttt{setLaneChangeMode(ego, 0)}) and the ego is placed with
        \texttt{moveToXY} (a teleport) $\Rightarrow$ no manoeuvre $\Rightarrow$ $v_y = 0$.
  \item Other vehicles are moved by the lane-change model, so their lateral speed is correct.
\end{itemize}

\paragraph{Check in SUMO.} The ego was moved $0.2~\mathrm{m}$ sideways every step ($2~\mathrm{m/s}$) with
\texttt{moveToXY} (scenario s05003, SUMO 1.27.1):

Constant lateral push $a_y = 3~\mathrm{m/s^2}$, $v_x = 15~\mathrm{m/s}$:

  \toprule
  time & old code: $y$ & new code: $y$ \\
  \midrule
  0.5 s & 0.08 m & 0.38 m \\
  1.0 s & 0.15 m & 1.50 m \\
  1.5 s & 0.23 m & 3.00 m \\
  3.0 s & 0.45 m & 7.50 m \\
  \bottomrule
\end{tabular}

\begin{itemize}
  \item Old: $\Delta y = \tfrac{1}{2} a_y \Delta t^2 \le 0.015~\mathrm{m}$ per step, i.e.\ about $0.15~\mathrm{m/s}$
        of drift (lane width $3.5~\mathrm{m}$).
  \item New: $v_y$ builds up to its $3~\mathrm{m/s}$ cap in $1~\mathrm{s}$; a lane change takes about $1.5~\mathrm{s}$.
\end{itemize}

\subsubsection*{Why the old code still shows some lateral movement}
\begin{itemize}
  \item The $\tfrac{1}{2} a_y \Delta t^2$ term accumulates under a sustained push (e.g.\ stuck behind a slow
        vehicle): $1.5~\mathrm{m}$ after $10~\mathrm{s}$ at $3~\mathrm{m/s^2}$.
  \item Fallback in \texttt{safe\_move\_ego}: if \texttt{moveToXY} fails, the ego is placed at the nearest lane
        centre (a jump of up to $1.75~\mathrm{m}$).
  \item $y$ is clamped to the safe road band, so the ego is pushed back inside instead of crashing at the edge.
\end{itemize}

\end{lstlisting}

\section{CMA-ES: the optimiser used in v14}\label{sec:cmaes}
Both the fixed base set (\texttt{v14/base}) and the adaptive policy (\texttt{v14/adaptive}) are trained with the
Covariance Matrix Adaptation Evolution Strategy (CMA-ES, N.\ Hansen, \emph{The CMA Evolution Strategy: A
Tutorial}, 2016). It is a derivative-free optimiser: it only needs a score for each candidate, which suits $J$
(a closed-loop SUMO success rate, noisy and without a gradient).

% ---------------------------------------------------------------------------
\subsection{Idea}
CMA-ES keeps a Gaussian \textbf{search distribution} $\mathcal{N}(m, \sigma^2 C)$ over the search vector
$x \in \mathbb{R}^N$:
\begin{itemize}
  \item $m$ (mean): the current best guess, \emph{where} to search;
  \item $\sigma$ (step size): \emph{how far} to search around $m$;
  \item $C$ (covariance, $N \times N$): the \emph{shape} of the search, stretched along directions that worked.
\end{itemize}
Each generation samples $\lambda$ candidates, scores them, moves $m$ to a weighted average of the best $\mu$, and
adapts $\sigma$ and $C$ from the step just taken. Two \textbf{evolution paths} remember the recent steps:
$p_\sigma$ (for the step size) and $p_c$ (for the covariance).

% ---------------------------------------------------------------------------
\subsection{Constants}
Only $\lambda$ (population size) and the start values $m_0, \sigma_0$ are chosen; everything else follows from
$N$ and $\lambda$ (standard defaults):
\begin{align*}
  \mu &= \lfloor \lambda/2 \rfloor, &
  w_i &= \frac{\ln(\mu + \tfrac12) - \ln i}{\sum_{j=1}^{\mu} \big(\ln(\mu + \tfrac12) - \ln j\big)},\quad i = 1, \dots, \mu, \\
  \mu_{\mathrm{eff}} &= \Big(\sum_{i=1}^{\mu} w_i^2\Big)^{-1}, &
  \chi_N &= \sqrt{N}\Big(1 - \tfrac{1}{4N} + \tfrac{1}{21N^2}\Big) \approx \mathbb{E}\|\mathcal{N}(0, I)\|, \\
  c_\sigma &= \frac{\mu_{\mathrm{eff}} + 2}{N + \mu_{\mathrm{eff}} + 5}, &
  d_\sigma &= 1 + 2\max\Big(0, \sqrt{\tfrac{\mu_{\mathrm{eff}} - 1}{N + 1}} - 1\Big) + c_\sigma, \\
  c_c &= \frac{4 + \mu_{\mathrm{eff}}/N}{N + 4 + 2\mu_{\mathrm{eff}}/N}, &
  c_1 &= \frac{2}{(N + 1.3)^2 + \mu_{\mathrm{eff}}}, \\
  c_\mu &= \min\Big(1 - c_1,\; \frac{2(\mu_{\mathrm{eff}} - 2 + 1/\mu_{\mathrm{eff}})}{(N + 2)^2 + \mu_{\mathrm{eff}}}\Big). &&
\end{align*}

\begin{center}
\small
\begin{tabular}{lcc}
  \toprule
  & \texttt{v14/base} ($N = 7$) & \texttt{v14/adaptive} ($N = 36$) \\
  \midrule
  $\lambda$, $\mu$ & 15, 7 & 15, 7 \\
  $w_1 \dots w_7$ & \multicolumn{2}{c}{$0.361,\ 0.237,\ 0.164,\ 0.113,\ 0.073,\ 0.040,\ 0.012$} \\
  $\mu_{\mathrm{eff}}$ & 4.29 & 4.29 \\
  $c_\sigma$, $d_\sigma$ & 0.386, 1.386 & 0.139, 1.139 \\

\end{tabular}
\end{center}
With $N = 36$ the covariance learns slowly ($c_1 + c_\mu \approx 0.005$ per generation): in 32 generations the
adaptive search is mainly driven by $m$ and $\sigma$, while the 7-dimensional base search also reshapes $C$
noticeably ($c_1 + c_\mu \approx 0.09$).

% ---------------------------------------------------------------------------
\subsection{Algorithm}
\textbf{Initialise:} $m = m_0$, $\sigma = \sigma_0$, $C = I$, $p_\sigma = p_c = 0$, $g = 0$.

\noindent\textbf{Repeat for every generation $g = 0, 1, 2, \dots$}
\begin{enumerate}
  \item \textbf{Sample.} Eigendecomposition $C = B D^2 B^{\top}$ ($B$: eigenvectors, $D$: square roots of the
        eigenvalues). For $k = 1, \dots, \lambda$:
        \[
          z_k \sim \mathcal{N}(0, I), \qquad y_k = B D z_k \sim \mathcal{N}(0, C), \qquad x_k = m + \sigma\, y_k .
        \]
  \item \textbf{Evaluate.} Score every candidate, $f_k = f(x_k)$ (lower is better), and sort:
        $f(x_{1:\lambda}) \le f(x_{2:\lambda}) \le \dots$, where $x_{i:\lambda}$ is the $i$-th best.
  \item \textbf{Move the mean.} Weighted average of the $\mu$ best steps:
        \[
          \bar y_w = \sum_{i=1}^{\mu} w_i\, y_{i:\lambda}, \qquad m \leftarrow m + \sigma\, \bar y_w .
        \]
  \item \textbf{Step-size path} (in whitened coordinates, so it is independent of the shape $C$):
        \[
          p_\sigma \leftarrow (1 - c_\sigma)\, p_\sigma + \sqrt{c_\sigma (2 - c_\sigma)\, \mu_{\mathrm{eff}}}\;
          C^{-1/2}\, \bar y_w, \qquad C^{-1/2} = B D^{-1} B^{\top}.
        \]
  \item \textbf{Stall indicator.} $h_\sigma = 1$ if
        $\dfrac{\|p_\sigma\|}{\sqrt{1 - (1 - c_\sigma)^{2(g+1)}}} < \big(1.4 + \tfrac{2}{N + 1}\big)\, \chi_N$,
        else $0$ (stops $p_c$ from growing while $\sigma$ is still increasing quickly).
  \item \textbf{Covariance path:}
        \[
          p_c \leftarrow (1 - c_c)\, p_c + h_\sigma \sqrt{c_c (2 - c_c)\, \mu_{\mathrm{eff}}}\; \bar y_w .
        \]
  \item \textbf{Covariance update} (rank-one from the path, rank-$\mu$ from this generation's best steps):
        \[
          C \leftarrow (1 - c_1 - c_\mu)\, C
            + c_1 \big( p_c p_c^{\top} + (1 - h_\sigma)\, c_c (2 - c_c)\, C \big)
            + c_\mu \sum_{i=1}^{\mu} w_i\, y_{i:\lambda}\, y_{i:\lambda}^{\top},
          \qquad C \leftarrow \tfrac12 (C + C^{\top}).
        \]
  \item \textbf{Step-size update:}
        \[
          \sigma \leftarrow \sigma \exp\!\Big( \frac{c_\sigma}{d_\sigma} \Big( \frac{\|p_\sigma\|}{\chi_N} - 1 \Big) \Big).
        \]
  \item $g \leftarrow g + 1$.
\end{enumerate}

\paragraph{What each update does.}
\begin{itemize}
  \item \textbf{Mean:} only the better half of the samples pulls $m$, the best one most ($w_1 = 0.36$). Because $m$
        is an average of several candidates, one lucky score moves it little.
  \item \textbf{Step size:} if successive mean steps point the same way, $\|p_\sigma\| > \chi_N$ and $\sigma$
        grows (the search is too timid); if they cancel, $\|p_\sigma\| < \chi_N$ and $\sigma$ shrinks (the search is
        circling an optimum). For random steps $\|p_\sigma\| \approx \chi_N$ and $\sigma$ stays.
  \item \textbf{Covariance:} the rank-one term stretches $C$ along the direction the mean has been moving over
        several generations ($p_c$); the rank-$\mu$ term stretches it along this generation's successful steps.
        Correlated parameters (good sets have, e.g., more $\lambda_{obs}$ \emph{and} less $\tau_y$) are therefore
        searched along their diagonal.
\end{itemize}

File: \texttt{v14/*/common.py} (\texttt{class CMAES}: \texttt{ask} = step 1, \texttt{tell} = steps 3--9).

with $J = \text{success rate} + 0.1 \cdot \text{mean progress}$ (progress $= 1$ for a success), and for the base
\[
  u_k = \frac{\log_{10} p_k - \log_{10} lo_k}{\log_{10} hi_k - \log_{10} lo_k}, \qquad
  [lo_k, hi_k] = \text{search range of parameter } k,
\]
so one unit of $u$ spans the whole log range and $\sigma$ means the same for every parameter.

\paragraph{Validation and selection.} CMA-ES only sees the training runs. Every 4 generations two points are scored
on validation (100 scenarios $\times$ 3 futures):
\begin{itemize}
  \item the \textbf{mean} $m$ (a new point, never one of the sampled candidates);
  \item the \textbf{best train candidate} so far, if a new one appeared.
\end{itemize}
The final set is the validated point (start set included) with the highest validation $J$; ties go to the earlier
generation. In all three v14 runs this was the mean $m$: base generation 30 (validation $J = 0.950$),
\texttt{base\_delta\_v} generation 32 ($0.875$), adaptive generation 12 ($0.978$). The best train candidates,
picked as the highest of many noisy training scores, dropped back on validation (e.g.\ adaptive generation 15:
train $J = 0.998$, validation $0.961$).

\section{The adaptive policy algorithm (v14)}
The DIPF controller itself is unchanged: every acceleration is still the clamped negative gradient of the
potential. The adaptive policy only \textbf{retunes four of the potential's parameters every $0.1~\mathrm{s}$}
from the traffic around the ego. It never outputs an acceleration, so a bad choice can reshape the field but
cannot command an arbitrary manoeuvre.

% ---------------------------------------------------------------------------
\subsection{Algorithm}
Every control step, just before the potential is evaluated:
\begin{align*}
  f_t   &= \text{features}(\text{80-value traffic encoding}) \in [0,1]^9 \\
  z^*_t &= \mathrm{clip}\big(W f_t + b,\; -\ln 10,\; +\ln 10\big)
          && W \in \mathbb{R}^{4\times 9},\; b \in \mathbb{R}^{4} \;\Rightarrow\; 40 \text{ numbers} \\
  z_t   &= z_{t-1} + \tfrac{\Delta t}{T}\,(z^*_t - z_{t-1})
          && \Delta t = 0.1~\mathrm{s},\; T = 1~\mathrm{s};\; z_0 = z^*_0 \\
  p_t   &= \mathrm{clamp}\big(p_0 \cdot e^{z_t},\; \text{limits}\big)
          && p = (\lambda_{obs},\, \tau_{y},\, \alpha,\, \text{obs\_radius\_ahead})
\end{align*}
\begin{itemize}
  \item $p_0$ = the trained fixed set from \texttt{v14/base} (CMA-ES over all 7 parameters).
        $W = 0, b = 0$ reproduces it exactly, so any gain comes from adapting.
  \item $e^{z}$: multiplicative and always positive; the clip keeps each parameter within $\times 0.1 \dots \times 10$ of $p_0$.
  \item Smoothing: the exponent moves $10\,\%$ of the way to its target each step, so a parameter follows a
        sudden change within about $1~\mathrm{s}$ instead of jumping.
  \item The other parameters ($s_x$, $\delta_{lane}$, $y_{margin}$, $\tau_x = 1$) stay at $p_0$.
  \item Sign constraint: the weights from \texttt{ttc\_front}, \texttt{ttc\_side\_front}, \texttt{drac\_front}
        to $\lambda_{obs}$ are $\ge 0$ (repulsion may only grow with danger).
\end{itemize}

File: \texttt{v14/adaptive/dipf\_controller.py} (\texttt{adapt\_parameters}), \texttt{policy.py}.
\begin{lstlisting}
enc = encode((x, y, vx, vy), nearby, road_bounds_y(), EGO_LENGTH, EGO_WIDTH)
f = pol.features(enc)                                     # 9 features in [0, 1]
z_target = clip(W @ f + b, -ln10, ln10)
z = z_target if z is None else z + min(1, dt/T) * (z_target - z)   (*\color{accent}\# smoothing*)
for k, name in enumerate(params):                         # lambda_obs, tau_y, alpha, radius
    value[name] = clamp(base[name] * exp(z[k]), *limits[name])
# ... then the unchanged DIPF step: U, grad U, a = clamp(-grad U), moveToXY
\end{lstlisting}

% ---------------------------------------------------------------------------
\subsection{Training}
\begin{itemize}
  \item No target value of $p_t$ exists, so the 40 numbers are trained directly on closed-loop outcome:
        $J = \text{success rate} + 0.1 \cdot \text{mean progress}$, takeover ($x \approx 100~\mathrm{m}$) to $x = 400~\mathrm{m}$.
  \item CMA-ES from $W = 0, b = 0$: $30$ generations $\times$ $15$ candidates, each scored on the same
        $100$ train scenarios $\times$ $2$ futures (same budget as the fixed base: $450$ candidates).
  \item Every 4 generations the search mean is scored on validation ($100 \times 3$ runs); the best one is kept
        (generation 12, validation success $0.730$ vs $0.647$ for the fixed set).
\end{itemize}

% ---------------------------------------------------------------------------
\subsection{What it learned}
\begin{itemize}
  \item $\lambda_{obs}$ (repulsion): rises sharply with a vehicle closing from behind/side
        (\texttt{ttc\_rear\_side} $+2.0$) or diagonally ahead ($+1.85$), and with tight lateral room ($+1.3$);
        falls behind a close but non-closing car (\texttt{gap\_front} $-1.7$), so the ego follows calmly.
  \item $\tau_y$ (lateral reach): grows with speed ($+1.5$), shrinks when closing in ahead ($-1.3$).
  \item $\alpha$: pinned at its $0.01$ floor in every step, so it does not really adapt.
  \item Look-ahead radius: about $\times 1.8$ of the fixed set ($\approx 174~\mathrm{m}$ vs $97~\mathrm{m}$),
        shorter in dense traffic.
\end{itemize}

\section{Constraints on the motion and on the potential (v14)}\label{sec:constraints}
The controller has two kinds of limits: \textbf{hard limits on the motion} (applied after the gradient, they
override the potential) and \textbf{built-in margins in the potential} (they shape the field, so the gradient
already keeps the ego away from the limits). Values are for \texttt{v14/base} and \texttt{v14/adaptive}
(\texttt{config.yaml}, \texttt{base\_best.json}); ego body $L \times W = 4.583 \times 1.748~\mathrm{m}$.

% ---------------------------------------------------------------------------
\subsection{Motion limits: acceleration, velocity, jerk}

  lateral speed $v_y$             & $-3.0~\mathrm{m/s}$ & $+3.0~\mathrm{m/s}$ & $v_y + a_y \Delta t$ \\
  heading (see below)             & \multicolumn{2}{l}{$|v_y| \le v_x \tan 15^\circ$} & after the $v_y$ clamp \\
  jerk $\dot a_x, \dot a_y$       & \multicolumn{2}{l}{\textbf{none}} & -- \\
  \bottomrule
\end{tabular}
\end{center}
\begin{itemize}
  \item The braking limit $9~\mathrm{m/s^2}$ is SUMO's emergency deceleration; the throttle limit is asymmetric
        ($3.2$). The flag \texttt{ego.limit\_acceleration: false} removes the acceleration clamp (speed limits stay).
  \item The acceleration is clamped \textbf{per axis} (box, not a friction circle): the ego may brake at
        $9$ and swerve at $3~\mathrm{m/s^2}$ at the same time.
  \item \textbf{No jerk limit} (since v9): the acceleration is the clamped gradient of the current step and may
        jump to any value in the box between two steps. The largest possible jump in one
        $\Delta t = 0.1~\mathrm{s}$ step is therefore
        $|\Delta a_x|/\Delta t = (3.2 + 9.0)/0.1 = 122~\mathrm{m/s^3}$ and
        $|\Delta a_y|/\Delta t = 6/0.1 = 60~\mathrm{m/s^3}$ (comfort limits are typically $1$--$2~\mathrm{m/s^3}$).
        The previous acceleration is stored (\texttt{prev\_ax}, \texttt{prev\_ay}) but not used.
  \item The only smoothing in the loop is on the \textbf{parameters} (adaptive policy, Section~\ref{sec:constraints-adaptive}),
        not on the acceleration.
\end{itemize}

File: \texttt{v14/*/dipf\_controller.py} (\texttt{ego\_control\_step}).
\begin{lstlisting}
ax = clamp(-dUx, -EGO_D_MAX, EGO_A_MAX)            # [-9.0, +3.2]
ay = clamp(-dUy, -EGO_AY_MAX, EGO_AY_MAX)          # [-3.0, +3.0]
# No jerk limit (v9): the commanded acceleration is the clamped gradient.   (*\color{codebad}\# no rate limit*)
vx_apply = clamp(vx + ax*dt, 0.0, EGO_MAX_SPEED)   # [0, 34]
vy_apply = clamp(vy + ay*dt, -EGO_VY_MAX, EGO_VY_MAX)
vy_cap   = vx_apply * TAN_MAX_HEADING               # tan(15 deg)
vy_apply = clamp(vy_apply, -vy_cap, vy_cap)
\end{lstlisting}

\subsection{Angle constraints}
\paragraph{Heading limit.} The ego's heading follows its velocity, $\theta = \arctan(v_y / v_x)$, and is passed to
\texttt{moveToXY}. It is capped at $\theta_{max} = 15^\circ$ by limiting the lateral speed:
\[
  |v_y| \le v_x \tan 15^\circ = 0.268\, v_x .
\]
\begin{itemize}
  \item Ties lateral to forward motion: no sideways sliding at low speed; at standstill $v_y = 0$
        (the heading keeps its last value).
  \item The $3~\mathrm{m/s}$ lateral cap is the binding one only above $v_x = 3/0.268 = 11.2~\mathrm{m/s}$;
        below that the heading cap is stricter (e.g.\ $v_x = 5~\mathrm{m/s} \Rightarrow |v_y| \le 1.34~\mathrm{m/s}$).
\end{itemize}

\paragraph{Angled body in the lane potential.} A turned ego is wider across the road. The lane walls use its
lateral half-extent at the current heading:
\[
  h(\theta) = \tfrac{L}{2}|\sin\theta| + \tfrac{W}{2}|\cos\theta|
\]
\begin{center}
\begin{tabular}{ccccc}
  \toprule
  $\theta$ & $0^\circ$ & $5^\circ$ & $10^\circ$ & $15^\circ$ (max) \\
  \midrule
  $h(\theta)$ & $0.874$ m & $1.070$ m & $1.259$ m & $1.437$ m \\
  \bottomrule
\end{tabular}
\end{center}
So a lane change towards the edge moves the wall up to $0.56~\mathrm{m}$ inwards. Note: the hard road-departure
check (\texttt{ego\_within\_road}) uses the unturned $W/2$, so the potential is the more conservative of the two.

\paragraph{Region angle in the obstacle potential.} $k'$ switches between its longitudinal and lateral form along the
diagonal of the combined box ($w = (W_{ego} + w_{eff})/2$, $l = (L_{ego} + l_{eff})/2$):
\[
  k' = \begin{cases}
    \big(1 - \tfrac{l}{|\Delta x|}\big)\sqrt{\big(\tfrac{\Delta x}{\tau_x}\big)^2 + \big(\tfrac{\Delta y}{\tau_y}\big)^2}
      & |\Delta y| \le \tfrac{w}{l}|\Delta x| \quad (\text{ahead / behind}) \\[4pt]
    \big(1 - \tfrac{w}{|\Delta y|}\big)\sqrt{\cdots} & \text{otherwise} \quad (\text{beside})
  \end{cases}
\]
i.e.\ the boundary is the corner direction $\arctan(w/l)$ from the road axis: $21.2^\circ$ (bike),
$23.8^\circ$ (auto), $21.9^\circ$ (car), $15.0^\circ$ (bus, truck). In each region the singular wall sits where the
two bodies touch on that axis.

\begin{itemize}

  \item Vehicles: SUMO's own collision detector on the actual sizes.

\subsection{Limits on the adapted parameters}\label{sec:constraints-adaptive}
The adaptive policy changes four potential parameters, each kept within three nested limits:
\begin{enumerate}
  \item \textbf{Relative}: $|z| \le \ln 10$ $\Rightarrow$ $p \in [\,0.1\,p_0,\; 10\,p_0\,]$.
  \item \textbf{Absolute}: clamp to the \texttt{v14/base} search range.
  \item \textbf{Rate}: smoothing with $T = 1~\mathrm{s}$ moves $z$ at most
        $\tfrac{\Delta t}{T} \cdot 2\ln 10 = 0.46$ per step $\Rightarrow$ a parameter changes by at most
        $\times 1.58$ (or $\div 1.58$) per $0.1~\mathrm{s}$.
\end{enumerate}
\begin{center}
\small
\begin{tabular}{lcccc}
  \toprule
  parameter & $p_0$ (base) & $\times 0.1 \dots \times 10$ & absolute limits & effective range \\
  \midrule
  $\lambda_{obs}$              & $190.7$  & $19.1$ -- $1907$    & $0.01$ -- $10^4$ & $19.1$ -- $1907$ \\
  $\tau_y$                     & $0.378$  & $0.038$ -- $3.78$   & $0.01$ -- $20$   & $0.038$ -- $3.78$ \\
  $\alpha$                     & $0.0209$ & $0.0021$ -- $0.209$ & $0.01$ -- $100$  & $\mathbf{0.01}$ -- $0.209$ \\
  $r_{ahead}$ (m)              & $97.5$   & $9.75$ -- $975$     & $10$ -- $250$    & $\mathbf{10}$ -- $\mathbf{250}$ \\
  \bottomrule
\end{tabular}
\end{center}
\begin{itemize}
  \item Bold: the absolute limit is the binding one. $\alpha$ is pinned at its $0.01$ floor in practice.
  \item Sign constraint: the weights from \texttt{ttc\_front}, \texttt{ttc\_side\_front}, \texttt{drac\_front}
        to $\lambda_{obs}$ are $\ge 0$ (enforced by reflection, $w \leftarrow |w|$).
  \item Fixed, not adapted: $s_x$, $\delta_{lane}$, $y_{margin}$, $\tau_x = 1$, $r_{behind} = 20~\mathrm{m}$,
        lateral band $8~\mathrm{m}$, the motion limits above. The policy cannot loosen any motion limit.
\end{itemize}

\section{Identical SUMO scenarios and futures (v14)}\label{sec:identical}
All v14 comparisons (base vs adaptive, the numerator variants) rely on every candidate meeting
\textbf{exactly the same traffic}. Three pieces make this possible: saved scenarios, futures, and
repeatable SUMO runs.

% ---------------------------------------------------------------------------
\subsection{Scenarios: saved starting states}
\begin{itemize}
  \item Created once by \texttt{step1\_make\_scenarios.py}: traffic runs for $30~\mathrm{s}$, the car nearest
        $x = 100~\mathrm{m}$ becomes the ego, and the full SUMO state is saved at that moment.
  \item Per scenario \texttt{scenarios/sNNNNN/}: \texttt{state.xml} (all vehicles, routes, RNG state),
        \texttt{ego.json} (the controller-held ego state $v_x, v_y$, heading), \texttt{meta.json} (seed, road length, start $x$).
  \item Saved \textbf{before} the controller acts, so a scenario does not depend on the DIPF parameters or the
        potential variant.
  \item All v14 sub-folders share one scenario folder, \texttt{v14/base/scenarios}
        (their \texttt{config.yaml} points \texttt{scenarios\_dir} to it).
  \item Seed splits: train 0--99, validation 400--499, test 5000--5299 (never used for training or selection).
  \item Guard: \texttt{meta.json} records the road length; every step refuses scenarios made on another road.
\end{itemize}

% ---------------------------------------------------------------------------
\subsection{Futures: several random continuations of one scenario}
\begin{itemize}
  \item A scenario fixes the \textbf{start}; the traffic after it is random (driver imperfection, speed deviation,
        lane-change decisions).
  \item Each scenario is reloaded with SUMO seeds $1, \dots, n$ (\texttt{--seed}): \textbf{future} $k$ = scenario
        + seed $k$. Same start, different random continuation.
  \item Futures per scenario: train $2$, validation $3$, test $3$ \;$\Rightarrow$\; one result is a success
        \emph{rate}, not a single lucky or unlucky run.
  \item \textbf{Common random numbers}: every candidate (parameter set or policy) is run on the same scenarios
        $\times$ futures, so differences come from the controller, not from the traffic. Results are compared
        run by run (paired McNemar test).
\end{itemize}
\begin{lstlisting}
cmd = [sumo, "-n", NET_FILE.name, "--load-state", "scenarios/sNNNNN/state.xml",
       "--step-length", "0.1", "--lateral-resolution", "0.25", ...]
cmd += ["--seed", str(future)]                       (*\color{accent}\# future 1, 2, 3, ...*)
\end{lstlisting}

% ---------------------------------------------------------------------------
\subsection{Repeatable runs: same scenario + same future $\Rightarrow$ same result}
\paragraph{Problem 1: address-space randomisation (ASLR).} SUMO orders some internal work by memory address.
Linux randomises memory addresses on every launch, so the same run (state, seed, commands) drew its random
numbers in a different order each time: after one step two vehicles $300~\mathrm{m}$ apart had swapped their
speed perturbations, and an identical run could end in success once and in a collision the next time.

\begin{center}
\begin{tabular}{lcc}
  \toprule
  10 repeats of the same run & default (ASLR on) & v14 (ASLR off) \\
  \midrule
  s00007, future 2 & 2 different outcomes & 1 \\
  s00003, future 1 & 4 (2 successes, 2 collisions) & 1 \\
  s00012, future 2 & 2 different outcomes & 1 \\
  \bottomrule
\end{tabular}
\end{center}

Fix: every SUMO process is started with address randomisation disabled (equivalent of \texttt{setarch -R}):
\begin{lstlisting}
def _kill_with_parent():               # preexec_fn: runs just before SUMO starts
    libc = ctypes.CDLL("libc.so.6", use_errno=True)
    libc.prctl(1, signal.SIGKILL)                                 # SUMO dies with its parent
    ADDR_NO_RANDOMIZE = 0x0040000                                 (*\color{accent}\# no ASLR:*)
    libc.personality(libc.personality(0xFFFFFFFF) | ADDR_NO_RANDOMIZE)
\end{lstlisting}

\paragraph{Problem 2: the result depended on the folder.} SUMO's memory layout also depends on the length of
its command line and environment. The same parameters run from \texttt{v14/base} and \texttt{v14/adaptive} gave
different outcomes (network path \texttt{.../base/...} vs \texttt{.../adaptive/...}, and the \texttt{PWD} variable).
Fix: identical command line and environment from every folder:
\begin{lstlisting}
env = {k: v for k, v in os.environ.items() if k not in ("PWD", "OLDPWD", "_")}
# relative "-n" path, run in the network's folder, fixed environment
proc = subprocess.Popen(cmd + ["--remote-port", str(port)], preexec_fn=_kill_with_parent,
                        cwd=str(NET_FILE.parent), env=env)
\end{lstlisting}

\paragraph{Checks.}
\begin{itemize}
  \item Repeating a run gives the identical outcome and progress (30 of 30 repeats).
  \item The same parameters give identical results from \texttt{v14/base} and \texttt{v14/adaptive}.
  \item The adaptive policy with all weights $0$ reproduces the trained fixed set run by run, and
        \texttt{adaptive/step3} reproduces \texttt{base/step3} exactly (success $0.646$, progress $0.780$).
  \item All runs must use the same SUMO binary: the scenarios were made with SUMO 1.27.1 (venv); SUMO 1.18
        (\texttt{/usr/share/sumo}) cannot load them. \texttt{sumolib.checkBinary} follows \texttt{SUMO\_HOME}.
\end{itemize}
